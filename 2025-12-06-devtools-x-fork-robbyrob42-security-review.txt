⏺ DevTools-X Security Review Report

  I've completed a comprehensive security audit of the devtools-x
  repository. Here are my findings:

  Executive Summary

  DevTools-X is a Tauri v2.2.0 desktop application providing 41+ developer
  utilities. While the application is generally well-engineered, I've
  identified several security concerns that warrant attention, particularly
  around permissions, credential storage, XSS vectors, and dependency
  vulnerabilities.

  Risk Level: MEDIUM-HIGH - The application has broad filesystem permissions
   and several security issues, but is mitigated by being a desktop app (not
   server-facing).

  ---
  Critical Findings

  1. Plain Text Credential Storage ⚠️ CRITICAL

  Location: src/Features/pastebin/Pastebin.tsx:37,103

  The GitHub API key is stored in plain text in browser localStorage:

  localStorage.getItem("github-api-key")
  localStorage.setItem("github-api-key", e.currentTarget.value)

  Risk: Any malicious code with DOM access can steal the API key.

  Recommendation: Use Tauri's secure store plugin or encrypt credentials
  before storage.

  ---
  2. XSS Vulnerabilities via dangerouslySetInnerHTML ⚠️ HIGH

  Two components render unsanitized user input:

  a) SVG Preview (src/Features/svg/Svg.tsx:43-45)
  <Box dangerouslySetInnerHTML={{ __html: `${svg}` }}></Box>
  Renders arbitrary SVG content from user files without sanitization.

  b) CSS Playground (src/Features/css/CssPlayground.tsx:45-46)
  <Box dangerouslySetInnerHTML={{ __html: `${html}<style>${css}</style>`
  }}></Box>
  Renders arbitrary HTML+CSS without sanitization.

  Risk: Malicious SVG/HTML files could execute JavaScript in the app
  context, potentially accessing Tauri APIs.

  Recommendation: Use DOMPurify or similar sanitization library before
  rendering user-provided content.

  ---
  3. Arbitrary File Access in Rust Backend ⚠️ HIGH

  Location: src-tauri/src/commands/hash.rs:14-15

  let mut f = fs::File::open(&file).unwrap();
  io::copy(&mut f, &mut hasher).unwrap();

  The hash command accepts file paths from frontend without validation and
  uses .unwrap() (panics on error).

  Risk:
  - No path validation allows reading any file the user has access to
  - Use of .unwrap() causes process crash on error instead of graceful
  handling

  Recommendation:
  - Validate file paths are within expected directories
  - Use proper error handling with Result types instead of .unwrap()

  ---
  4. Broad Tauri Permissions ⚠️ HIGH

  Location: src-tauri/capabilities/default.json

  "permissions": [
    "fs:write-all",  // Full filesystem write access
    "sql:allow-execute",  // Arbitrary SQL execution
    "clipboard-manager:allow-write-text",  // Clipboard access
    "dialog:default",  // File dialogs
    "process:allow-restart"  // Process control
  ]

  Risk: A compromised frontend or malicious script could:
  - Write/modify any file the user can access
  - Execute arbitrary SQL queries
  - Restart the application

  Recommendation: Use more granular permissions where possible (e.g., scoped
   file access).

  ---
  5. Weak Content Security Policy ⚠️ MEDIUM

  Location: src-tauri/tauri.conf.json:73-106

  "csp": {
    "default-src": ["'self'", "blob:", "data:", "http:", "https:", ...],
    "script-src": ["'self'", "'unsafe-inline'"],
    "style-src": ["'self'", "'unsafe-inline'"],
    "worker-src": ["'self'", "blob:", "https://unpkg.com"],
    "dangerouslyDisableAssetCspModification": ["style-src"]
  }

  Issues:
  - 'unsafe-inline' allows inline scripts/styles (XSS risk)
  - http: and https: allowed for all domains in default-src
  - Workers can load from unpkg.com CDN
  - Asset CSP modification disabled for styles

  Recommendation: Tighten CSP to specific domains needed, remove
  'unsafe-inline' if possible.

  ---
  High Priority Findings

  6. Poor Error Handling in Rust Code ⚠️ HIGH

  Multiple Rust commands use .unwrap() extensively, causing panics instead
  of graceful error handling:

  - src-tauri/src/commands/hash.rs:14-15 - File operations
  - src-tauri/src/commands/ping.rs:118,121,132,151,155,170 - Network
  operations
  - src-tauri/src/commands/image.rs:20,25,41,48,61,66 - Image processing
  - src-tauri/src/main.rs:191 - Window operations

  Risk: Application crashes on unexpected input instead of returning errors.

  Recommendation: Replace .unwrap() with proper Result handling using ?
  operator or match.

  ---
  7. Unrestricted REST Client (SSRF-like) ⚠️ MEDIUM-HIGH

  Location: src/Features/rest/SingleTab.tsx:63-69

  const res = await fetch(url, {
    method,
    headers: parseKV(headersCopy),
    body: ...
  })

  The REST client can make arbitrary HTTP requests to any domain with custom
   headers.

  Risk:
  - Could be used to scan internal network from user's machine
  - Could make requests appearing to come from the user
  - No CORS protection since it's native fetch

  Recommendation: Consider adding warnings when accessing local network
  ranges (127.0.0.1, 192.168.x.x, etc.).

  ---
  8. ICMP Ping Requires Elevated Privileges ⚠️ MEDIUM

  Location: src-tauri/src/commands/ping.rs

  The app uses raw ICMP packets via surge-ping library.

  Risk:
  - Requires elevated privileges on some systems
  - Could be used for network reconnaissance
  - No rate limiting on ping requests

  Recommendation: Document privilege requirements and consider adding rate
  limits.

  ---
  Medium Priority Findings

  9. Critical Dependency Vulnerabilities 🔴

  Yarn audit found 11 vulnerabilities:

  Critical Severity (2):

  1. happy-dom (used by linaria/wyw-in-js)
    - CVE-2024-51757: Server-side code execution via <script> tag
    - CVE-2025-61927: VM Context escape leading to RCE
    - Versions: 10.8.0, 12.10.3 (vulnerable)
    - Fix: Upgrade to happy-dom >=20.0.0

  Moderate Severity (9):

  2. esbuild (used by vite) - CVE: CORS bypass allows arbitrary requests
  3. js-yaml - CVE-2025-64718: Prototype pollution
  4. vite (5.4.12) - Multiple CVEs:
    - CVE-2025-30208: server.fs.deny bypass with ?raw??
    - CVE-2025-31125: File disclosure via ?inline&import
    - CVE-2025-32395: Invalid request-target bypass
    - CVE-2025-46565: File bypass with /. pattern
    - CVE-2025-31486: Bypass with .svg or relative paths
    - CVE-2025-58751: Symlink bypass for public directory
  5. brace-expansion - CVE-2025-5889: ReDoS vulnerability

  Recommendation:
  # Update critical dependencies
  yarn upgrade vite@latest
  yarn upgrade js-yaml@^4.1.1
  yarn upgrade happy-dom@^20.0.0

  ---
  10. SQL Injection Risk Mitigated ✅ LOW RISK

  Location: src/Features/snippets/Snippets.tsx

  The app uses parameterized queries for SQLite, which properly prevents SQL
   injection:
  await db.execute("INSERT INTO snippets (...) VALUES ($1, $2, ...)",
  [title, code, ...])

  Status: No action needed - proper implementation.

  ---
  11. Auto-Update Mechanism Trust ⚠️ LOW-MEDIUM

  Location: src-tauri/tauri.conf.json:55-60

  "updater": {
    "endpoints": ["https://github.com/fosslife/devtools-x/releases/latest/do
  wnload/latest.json"],
    "pubkey": "dW50cnVzdGVkIGNvbW1lbnQ6..."
  }

  Risk:
  - Trust in GitHub releases and minisign signature
  - No additional integrity checks
  - Depends on GitHub's security

  Status: Acceptable risk for most users, but note the dependency chain.

  ---
  Low Priority Findings

  12. Devtools Auto-Open ℹ️ INFO

  Location: src-tauri/src/main.rs:188-194

  #[cfg(debug_assertions)]
  app.get_webview_window("main").unwrap().open_devtools();

  if process_arg.contains(&"--debug".to_string()) {
    app.get_webview_window("main").unwrap().open_devtools();
  }

  Devtools automatically open in debug mode or with --debug flag.

  Risk: Minor - could expose internal state if user accidentally runs in
  debug mode.

  ---
  13. No HTTPS Enforcement ℹ️ INFO

  The REST client allows HTTP connections without warnings.

  Recommendation: Consider warning users when making HTTP (non-TLS)
  requests.

  Architecture Analysis

  Positive Security Features ✅

  1. Tauri Framework: Better security than Electron (smaller attack surface)
  2. Parameterized SQL: Prevents SQL injection
  3. IPC Isolation: Frontend-backend separation via Tauri commands
  4. File Dialogs: User must explicitly select files (can't read arbitrary
  files without interaction)
  5. Update Signatures: Uses minisign for update verification

  Is This Malware?

  1. A user opens a malicious SVG/CSS file
  2. A user's GitHub API key is exposed
  3. The app is compromised via dependency vulnerabilities

  These are security issues that should be fixed, not indicators of
  malicious intent.
